# Phase 1 → Phases 2–11 Decision Map

What Phase 1 actually found, and what each finding forces the later phases to do. Full workings are
in [`data_audit.md`](data_audit.md) and the evidence notes it links.

**The short version.** The research can proceed as designed for Targets A and B — the funding level
on each venue and the cross-venue spread — using data that already exists, back to January 2025 for
both venues together. The third target, Target C (how far the funding you can see mid-hour ends up
moving before it settles), cannot be studied from history on either venue: Hyperliquid's archived
running value is an approximation that never lands exactly on the settled rate, and Lighter's
running value is exact but was never archived by anyone. So Target C starts accumulating the day a
recorder is switched on. That makes the always-on recorder the first thing Phase 2 should build,
not the last — every day of delay is a day of Target C data that cannot be recovered later.

| Funding units, sign, interval per venue | HL: dimensionless fraction, per hour, signed directly, 10 dp (`1e-10`), baseline `0.0000125`. Lighter: **percent**, per hour, unsigned magnitude plus a separate `direction` field, truncated (not rounded) to 4 dp. Both 1 h. Sign senses agree once applied: positive = longs pay shorts (HL checked 245/245 on data; Lighter verified on a genuinely negative market, `CAP`/212). [P4](evidence/P4-hl-api-crosscheck.md), [P5](evidence/P5-lighter-fundings.md), [P7](evidence/P7-funding-formulas.md) | Phase 4 normalisation of F_t | Normalise every Lighter rate to the common basis **before** anything else: `F = (rate/100)` if `direction == "long"` else `−(rate/100)`. A raw `rate` used as-is is 100× too large and unsigned — the single most likely silent bug in Phase 4. Add an assertion that no Lighter rate enters a model without passing through the signing function. **Effective precision of any spread is `1e-6`, not `1e-10`** (Lighter's 4-dp truncation binds), which sets the floor on what a "small" spread change can mean |
| Settlement timing and alignment across venues | Both venues settle hourly on the hour, and on both a row stamped `T` covers the interval `[T−1h, T)`. Lighter's convention verified directly against the live API; HL's is an **inference** from P4's alignment test (closing alignment's mean signed error is ~70× smaller and unsigned, opening's is one-signed). [P5](evidence/P5-lighter-fundings.md), [P9](evidence/P9-live-probe.md), [P4](evidence/P4-hl-api-crosscheck.md) | Pairing of S_t (Phase 4) | Hours pair one-to-one with **no offset** — `S_t = F_HL(t) − F_Lighter(t)` on the shared hourly grid. Carry the inference label on HL's convention: if a later result looks systematically shifted by one hour, re-test the HL alignment first. Both venues settle simultaneously, so no venue leads the other and no lag term is needed for alignment |
| Intra-hour OI/price availability per venue | HL: **historical**, 1-minute, from 2023-05-20 — `open_interest, mark_px, mid_px, oracle_px, day_ntl_vlm, impact_bid_px, impact_ask_px`, all changing on essentially every sample. Lighter: **no native intra-hour history of anything**; 0xArchive supplies OI + mark/oracle/index price at ~10 s from 2025-08-25 at 84–97% completeness, and live is `market_stats` websocket only. [P1](evidence/P1-hl-asset-ctxs.md), [P6](evidence/P6-lighter-market-state.md), [P8](evidence/P8-oxarchive.md) | Phase 7 features: historical vs prospective | Intra-hour features (OI change within the hour, price drift since settlement, impact-book skew) are **historical on HL, prospective-or-vendor on Lighter**. Any model mixing HL intra-hour features with Lighter hourly ones must record which side each feature came from |

Lighter: `/api/v1/candles` gives true per-bucket base (`v`) and quote (`V`) volume, ≥1 y at 1 h and ≥180 d at 1 m. [P1](evidence/P1-hl-asset-ctxs.md), [P6](evidence/P6-lighter-market-state.md) | Phases 2, 3, 7 | Volume is available historically on both — no prospective gap. | Premium availability per venue | HL: settled-hour average premium on `fundingHistory` (reproduces settled funding 245/245), plus per-minute archived premium back to 2023-05-20; the venue's true 5-second samples are **not public anywhere**. [P7](evidence/P7-funding-formulas.md), [P6](evidence/P6-lighter-market-state.md), [P8](evidence/P8-oxarchive.md), [P10](evidence/P10-rebuild.md) | Premium feature; Target C inputs | Premium as a feature is **historical on HL, prospective-only on Lighter**. Five hard requirements come out of P9's own failure (next row) |
| Recorder engineering requirements (from P9's stall) | The P9 run lost 95 minutes of both venues' data. Diagnosis: websocket snapshot writes were gated on a REST poll inside the same `try`, and one REST call blocked for **84 minutes** despite a `timeout=30` client; the recorder also overran its own deadline by 77 minutes because the deadline was only checked between cycles. The feed itself never stalled (all 1,631 snapshots had `n_msgs > 0`) and the venue was healthy; host suspension is the leading explanation (**inference** — no host logs kept). [P9](evidence/P9-live-probe.md) | Phase 2 recorder design | Five requirements, all mandatory: **(1)** never gate feed recording on a REST poll — websocket snapshots write on their own timer in a task no HTTP call can block; **(2)** detect a stalled feed explicitly — keep an `n_msgs` counter on every snapshot, force a reconnect and alert after 2–3 consecutive zero-message intervals, and mark or skip rather than silently re-emitting the last value; **(3)** enforce timeouts out-of-band with an external watchdog (`asyncio.wait_for`), since a client-level timeout did not bound an 84-minute read; **(4)** detect wall-clock jumps and host suspension — any inter-cycle gap beyond ~2 intervals writes an explicit gap record, and the deadline is re-checked inside the cycle; **(5)** alert on **coverage**, not record counts — the lost hour showed up as 1,631 vs 1,638 records, a 0.4% difference no count-based check would catch, so monitor expected-vs-actual snapshots per market per hour |
| 0xArchive $/month at research scale | A 50-market × 1-year Lighter backfill of funding + OI + trades is estimated at **480,000–510,000 credits**, from a corroborated ~10 s cadence (the vendor's own `total_records` field is unreliable — 900–9,000× its own `sample_count` — and must not be used for budgeting). Free tier: 50,000/mo (the account's quota changed to 200,000 mid-probe, vendor-side) and data calls limited to ~the last 30 days. **Build $49/mo, 80M credits** covers the backfill at ~0.6% of quota; Pro ($199/mo) is unnecessary. Whether Build itself unlocks >30-day calls is **inferred from tier naming, not tested**. [P8](evidence/P8-oxarchive.md) | Paid tier in Phase 2? | **Not needed for the core plan.** Targets A and B run on free native venue data; Target C is prospective regardless of any tier. Buy Build ($49/mo) only if Phase 7 wants Lighter intra-hour OI/index-price history back to 2025-08-25, or Phase 3 wants a Lighter-OI point-in-time universe before the recorder's start. If it is bought, **first test one call with `start` older than 30 days** to confirm the tier actually unlocks history, and budget one month, not a subscription — the backfill is a one-off |

| Cross-venue symbol matching | HL's `k`-prefixed markets (`kPEPE`, `kBONK`, `kFLOKI`, `kSHIB`, …) correspond to Lighter's `1000`-prefixed ones (`1000PEPE`, …) and do **not** join on an exact symbol match. The both-venues candidate set was 95 markets out of 233 HL and 246 Lighter; these pairs were silently excluded. [P0](evidence/P0-sample.md) | Phase 3 universe size | Phase 3 must add an alias table (`k*` ↔ `1000*`, and re-check for other denomination prefixes) before fixing the universe, or it will quietly drop a whole class of high-funding memecoin markets that are exactly the mid/small-cap segment this research targets. Note the denomination differs by 1000×, so prices and sizes need scaling, though funding **rates** are unaffected |
| Funding formulas confirmed on both venues | HL: `F_8h = P + clamp(0.0001 − P, ±0.0005)`, `F_hourly = clamp(F_8h/8, ±0.04)` — 245/245 off-baseline and 494/494 total hours within `1e-10`. Lighter (percent): `trunc4(clamp(P + clamp(0.01 − P, ±0.05), ±4) / 8)` with multiplier 1.0 — 16/16 off-baseline and 28/28 total, **exact to the reported digit**. Lighter's rests on 28 market-hours from a single 3h52m window, 7 markets, all positive; the 4% clamp and non-crypto multipliers are untested.
