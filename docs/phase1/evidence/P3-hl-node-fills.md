## Findings
- **No decode failures**: all `.lz4` files fetched (including the 15-byte empty `node_trades` file) decoded without error via `decode_lz4`; no alternate container format was encountered, so no new decoder was needed.
- **Date range / continuity**: `node_fills/` (2025-05-25 → 2025-07-27) is directly superseded by `node_fills_by_block/` (2025-07-27 → present, 2026-09-19) — the handoff date matches exactly, giving continuous fills coverage from **2025-05-25 to today** across the two datasets (schema changes once, at the handoff: flat `[address, fill]` list → block-grouped `events` list). `node_trades/` (2025-03-22 → 2025-06-21) predates and briefly overlaps `node_fills/`, but its last leaf is effectively empty (0 lines), suggesting it was deprecated/wound down around mid-2025 in favor of `node_fills`.
- **File granularity**: hourly, for all three datasets (`hourly/YYYYMMDD/H.lz4`, H = 0–23, one file per hour of that UTC day). Partial day counts observed (12 files for today 20260919, in progress; 9 files for 20250727, the schema-switch day) are consistent with hourly cadence, not gaps.
- **Fields → signed flow**: each fill row has `side` (`"B"`/`"A"`, i.e. which side of the book that leg matched — the paired other leg of the same trade is the opposite side) and `crossed` (bool — whether that specific leg was the taker/aggressor order that crossed the book). Combining `side` + `crossed` identifies the taker and its direction for every trade, and `dir` (`Open/Close Long/Short`) additionally disambiguates position-change intent. This is enough to reconstruct **signed taker (aggressor) trade flow** per coin per block. Fee sign (`fee` negative for the passive/maker leg, e.g. `-0.000148` above) is a secondary cross-check for which leg was the maker.
- **Coin identification**: plain names (`"FARTCOIN"`) in the 2025-07 `node_fills/` sample, but a namespaced form (`"xyz:MU"`) in the 2026-09 `node_fills_by_block/` sample. This indicates some markets carry a prefix (observed: `xyz:`) not seen in the `asset_ctxs`/L2 archive coin names for the 7 P0 sample coins — not confirmed here whether the P0 sample coins ever appear namespaced, since this probe downloaded whichever file was smallest, not one filtered to sample coins. Flagged as an open issue.
- **Coverage is whole-network, not per-coin**: unlike `asset_ctxs` or the L2 archive, fills files are not split by coin — every fill across every market in a hydrated block/hour is in one file. Using this as a signed-flow source means downloading (and filtering) the full file regardless of how many coins are needed.
- **Extrapolated cost (1 year, `node_fills_by_block/` schema, whole-network)**: median 34,323,535 bytes/hour × 24 × 365 = 300,674,166,600 bytes ≈ 300.7 GB/year → egress at $0.09/GB ≈ **$27.06/year**; request charges (`head`+`get` per hourly file: 8,760 × 2 × $0.000005 ≈ $0.09) → **total ≈ $27.15/year** to mirror one full year of whole-network fills. (Arithmetic: 34,323,535 × 8,760 = 300,674,166,600 bytes = 300.67 GB × $0.09 = $27.06; + $0.088 requests.) This is per year of the *entire* network's fills, not per coin — filtering to specific coins happens after download, so cost does not scale down with fewer coins.
- **Gaps**: only checked via first/last-leaf descent (4 levels: dataset → `hourly` → date → file), not a full day-by-day scan — an internal gap inside either date range (a missing day or hour) would not have been caught by this probe.

## Conclusion
`node_fills_by_block/` (continued from `node_fills/`) is a **usable historical signed-trade-flow source for HL, from 2025-05-25 onward** (continuous coverage to today across the schema handoff on 2025-07-27). It is whole-network (not pre-split by coin, so full-file download + local filtering is required), moderately priced to mirror in full (~$27/year, well within a real research budget though far more than P2's L2 archive), and its `side`/`crossed`/`dir` fields are sufficient to derive signed aggressor flow per coin per block. `node_trades/` is **not usable** — its most recent data (last leaf, 2025-06-21) is empty, and it predates/is superseded by `node_fills/`.
